## 3. Verdict

**The eleven hardening commits do what they say, and nothing in them weakens the script.** Every refusal tried
failed closed. The new checks are the right ones except for two that are too coarse to act on (P2, P3). No High
finding.

**One thing needs attention before 0.4.2 is tagged (P1):** with `main` now ahead of the release commit, the
commands in RELEASING.md tag the tip of `main` as `v0.4.2`, not `a23c13e`, and no check notices. Today it is
harmless only because those commits aren't pushed.

**Merge: yes**, after P1's doc line. P2 and P4 are worth fixing in the same branch; the rest can wait.

## 5. Design: are these the right checks

- **Right, and quiet until needed:** submodules, the bare `diff` attribute, NUL bytes, files inside the clone, fsck
  on fetch, the jar checksum. On both real diffs none of them, nor the bidi, invisible or control warnings, printed
  anything.
- **Noise:** the non-ASCII list (P3), and the environment warning in a VS Code terminal (P6). Both need a reason to
  act on, or they teach the owner to skim step 1 and step 3.
- **Environment and config warnings (N2, N3):** best effort by nature. `remote.*.vcs`, `remote.*.proxy`,
  `core.alternateRefsCommand`, `http.sslVerify` and an `ext::` URL aren't warned about (checked); the URL is shown
  at the fetch. The trusted-clone model covers them. Don't grow the list further; the comment at `:49-52` states the
  boundary honestly.
- **Still missing:** P1's guard is the one check whose absence can produce a wrong, unmovable tag. Then P5.
- **Size:** 512 lines, up from 419, which the last review already called the limit of what can be read by eye.
  P2, P3 and P9 can be fixed without adding lines overall if the four awk scans share one header-aware pass.

## 7. What is done well

- **The attribute check is exact.** Of 16 forms, only those that really force a text diff (bare `diff`, through a
  macro, with CRLF, tab or a quoted pattern) are refused; `diff=java`, `diff=true` and `-binary` don't force text
  and aren't refused.
- **Two layers for binaries.** A file git calls text because its first NUL comes late is caught by the NUL count; a
  changed jar is always binary because the old side is. Neither depends on the other.
- **The jar checksum never comes from the repository.** `gradle-wrapper.jar.sha256` is ignored, the Gradle version
  from the properties file is only a hint, and the hash isn't shown before the prompt.
- **Patterns in one place.** `BIDI_RE` and `INV_RE` feed both the display filter and the warnings, the comments
  list the code points, and the list matches the bytes exactly: no code point missed, none marked by mistake.
- **The self-test grew with the filter,** so an awk that can't match bytes stops the script before any review.
- **Commit discipline.** One fix per commit, each message saying what and why; docs in a separate commit.
- **The agent check earned its place:** it caught a real exposure on the first dry run, and the fix (key outside
  `~/.ssh`) removes the cause instead of working around the agent.
- **Fail-closed throughout:** every refusal provoked ended the run before anything was changed.
